# Common Search

## 1. 목적
통합검색 및 각 탭별(모듈별, 나중에 모듈이 탭으로 이동하면서 유저가 볼 것이므로) Search(검색)에 관한 공통적인 규칙을 정의한다.

## 2. 기능

### 2.1 x표시로 검색 및 인스턴트 검색 해제
- 일반검색, 상세검색, 인스턴트 검색 등으로 검색이 되었을 시, 각 입력창에 x 표시로 검색결과를 해제하고 원래의 전체 결과 list를 즉각 다시 볼 수 있어야 한다. 

### 2.2 인스턴트 검색
- 통합 검색창이 있는 경우 인스턴트 검색이 가능해야 한다.
- 인스턴트 검색은 한글, 영문(대소문자), 숫자 1글자 기준으로 작동한다.
- Search의 인스턴트 검색에서 한글의 1글자는 초성+중성 또는 초성+중성+종성을 기준으로 하고 초성 자음이나 모음만으로는 검색되지 않는다. 즉, IME composition 중에는 검색하지 않고 composition이 완료된 완성형 한글부터 검색한다
- 인스턴트 검색은 “입력한 문자열로 시작하는 값” 기준으로 검색된다. 즉, "서울중랑물재생센터"라는 곳이 있으면 "서"로는 검색되지만 "중"으로는 검색되지 않는다. 즉, prefix 검색이며 LIKE '검색어%' 이다.

## 3. 작동상태

### 3.1 한글입력
- 검색창에 한글입력의 경우 키보드의 오른쪽 화살표(→)를 누르지 않아도 입력이 완성된 것으로 판정해야 한다.
- 바로 위의 판정은 인스턴트 검색의 경우 중요하다.

### 3.2 검색창
- Search 탭 진입시 통합검색이 있으면, 마우스커서로 누르지 않아도 통합검색에 입력커서(caret)이 나타나고, 바로 입력 가능해야 한다.

### 3.3 인스턴트 검색
- 150~250ms debounce : 사용자가 빠르게 입력할 때, 타이핑이 잠깐 멈춘 뒤 한 번만 검색하게 200ms 정도 debounce를 주어 0.2초 동안 추가 입력이 없을 때 검색하게 한다.
- SQL LIMIT 100 : 인스턴트 검색 시 DB 조회 결과를 최대 100건으로 제한한다
- "검색 결과 100건 이상" 표시 : 검색결과가 100건이 넘어가면 UI에 표시를 해주고 특정한 버튼을 누르면 더 많은 검색결과를 볼 수 있게 해야한다. 100건 초과 여부 확인을 위해 최대 101건을 조회하며, 101건 이상이면 "검색 결과 100건 이상"으로 표시한다.
- 새 입력이 오면 이전 검색 취소 : 예를 들어 "삼"을 검색한 이후에, "삼성"을 검색하면 "삼"의 검색결과는 필요없다. 이전 검색의 응답이 새 검색보다 늦게 도착하더라도 최신 검색결과를 덮어쓰지 않아야 한다.
